Security Policy

🛡️ Sécurité d'Aura · Deen

La sécurité des utilisateurs et l'intégrité du projet Aura · Deen sont importantes.

Nous encourageons toute personne qui découvre une vulnérabilité à la signaler de manière responsable afin qu'elle puisse être examinée et corrigée.

---

🚨 Signaler une vulnérabilité

Si vous découvrez une vulnérabilité de sécurité dans Aura · Deen, évitez de publier immédiatement les détails techniques dans une issue publique.

Contactez directement le responsable du projet avec :

- une description de la vulnérabilité ;
- les étapes permettant de la reproduire ;
- l'impact potentiel ;
- les fichiers ou fonctionnalités concernés ;
- toute information permettant de faciliter l'analyse.

Pour les vulnérabilités sensibles, fournissez uniquement les informations nécessaires à leur compréhension et à leur correction.

---

🔒 Divulgation responsable

Nous demandons aux chercheurs et contributeurs de laisser un délai raisonnable au projet pour analyser et corriger une vulnérabilité avant de publier publiquement les détails.

Une fois le problème corrigé, une communication publique peut être effectuée lorsque cela est approprié.

---

🌐 Sécurité côté client

Aura · Deen est principalement une application web exécutée côté client.

Les utilisateurs doivent également maintenir leur navigateur et leur système à jour et utiliser des versions récentes des navigateurs compatibles.

---

🔐 Données personnelles

Aura · Deen est conçu avec une approche privilégiant la confidentialité.

Les préférences, la progression et certaines statistiques peuvent être stockées localement sur l'appareil de l'utilisateur.

Les contributeurs ne doivent jamais ajouter au dépôt :

- mots de passe ;
- clés API privées ;
- tokens d'authentification ;
- données personnelles d'utilisateurs ;
- identifiants ou informations confidentielles ;
- fichiers contenant des secrets.

Ne commitez jamais de secret dans Git.

---

📦 Dépendances externes

Toute nouvelle dépendance ou ressource externe doit être examinée avant son intégration.

Les contributeurs doivent notamment vérifier :

- sa provenance ;
- sa licence ;
- sa réputation ;
- les permissions demandées ;
- les risques de sécurité connus.

---

🗂️ Contenus et fichiers du dépôt

Les fichiers ajoutés au dépôt doivent être vérifiés avant leur publication.

Il est notamment recommandé de contrôler :

- les fichiers JavaScript ;
- les fichiers JSON ;
- les fichiers audio ;
- les ressources externes ;
- les URLs ;
- les dépendances ;
- les scripts exécutables.

Tout fichier suspect ou provenant d'une source non fiable ne doit pas être ajouté au projet.

---

⚠️ Ce qui ne constitue pas une vulnérabilité

Les problèmes suivants peuvent généralement être signalés comme des issues normales plutôt que comme des vulnérabilités :

- erreurs d'affichage ;
- fautes de texte ;
- problèmes d'interface ;
- fonctionnalités manquantes ;
- problèmes de compatibilité ;
- suggestions d'amélioration.

En cas de doute, privilégiez toutefois un signalement privé lorsque le problème pourrait avoir un impact sur la sécurité.

---

🔄 Versions concernées

La branche principale ("main") constitue la référence actuelle du développement.

Les corrections de sécurité sont appliquées en priorité aux versions activement maintenues.

---

🙏 Merci

Merci à toutes les personnes qui contribuent à identifier et corriger les problèmes de sécurité.

Les signalements responsables permettent de rendre Aura · Deen plus fiable et plus sûr pour tous.

Contributing to Aura · Deen

Merci de votre intérêt pour Aura · Deen 🌿

Aura · Deen est un projet open source conçu pour faciliter l'accès au Coran et à différents contenus d'apprentissage islamique dans une interface moderne, simple et respectueuse.

Toute contribution est la bienvenue : code, correction de bugs, amélioration de l'interface, documentation, suggestions ou signalement de problèmes.

---

🌿 Avant de contribuer

Avant toute contribution, nous vous recommandons de consulter :

- "README.md" — présentation du projet
- "CODE_OF_CONDUCT.md" — règles de conduite
- "LICENSE" — licence du projet
- "SECURITY.md" — signalement des problèmes de sécurité

En contribuant au projet, vous acceptez de respecter ces documents.

---

💡 Types de contributions

Vous pouvez contribuer de plusieurs manières.

💻 Code

Vous pouvez :

- corriger des bugs ;
- améliorer les performances ;
- améliorer l'accessibilité ;
- améliorer l'interface utilisateur ;
- ajouter de nouvelles fonctionnalités ;
- améliorer la compatibilité mobile ;
- améliorer le fonctionnement hors ligne.

🎨 Interface et expérience utilisateur

Les améliorations concernant :

- le design ;
- la navigation ;
- la lisibilité ;
- le responsive design ;
- l'accessibilité ;
- l'expérience sur mobile ;

sont également les bienvenues.

📚 Données et contenu

Les contributions concernant les données religieuses doivent être traitées avec une attention particulière.

Avant de proposer du contenu, vérifiez :

- sa source ;
- sa référence ;
- son authenticité lorsque cela est pertinent ;
- ses conditions de redistribution ;
- sa licence.

Ne soumettez pas de contenu dont vous ne disposez pas des droits de redistribution.

---

🙏 Contenu religieux

Aura · Deen ne doit pas être utilisé pour générer ou modifier arbitrairement des textes religieux.

Lorsqu'une contribution concerne le Coran, les hadiths, les invocations ou tout autre contenu religieux :

1. indiquez clairement la source ;
2. fournissez la référence lorsque cela est possible ;
3. évitez toute modification du texte original sans justification ;
4. signalez toute erreur découverte dans les données existantes ;
5. respectez les droits associés aux traductions, audios et autres contenus tiers.

En cas de doute concernant une donnée religieuse, il est préférable de signaler le problème avant de l'intégrer au projet.

---

🐛 Signaler un bug

Avant de créer une issue, vérifiez si le problème n'a pas déjà été signalé.

Lors du signalement, indiquez si possible :

- le problème rencontré ;
- les étapes permettant de le reproduire ;
- le comportement attendu ;
- le comportement observé ;
- l'appareil et le navigateur utilisés ;
- une capture d'écran si elle est utile.

Un titre clair permet également de faciliter le traitement de l'issue.

---

🚀 Proposer une fonctionnalité

Les nouvelles idées sont les bienvenues.

Avant de proposer une fonctionnalité importante, vous pouvez ouvrir une issue afin d'en discuter.

Expliquez :

- le problème que la fonctionnalité cherche à résoudre ;
- son fonctionnement proposé ;
- pourquoi elle serait utile aux utilisateurs ;
- les éventuels effets sur les fonctionnalités existantes.

---

🔀 Pull Requests

Pour contribuer au code :

1. Forkez le dépôt.
2. Créez une nouvelle branche.
3. Effectuez vos modifications.
4. Testez vos modifications.
5. Vérifiez qu'elles n'introduisent pas de régression.
6. Faites un commit clair.
7. Ouvrez une Pull Request.

Exemple :

git clone https://github.com/Chacoul31/Aura-deen.git
cd Aura-deen

git checkout -b feature/ma-fonctionnalite

git add .
git commit -m "Add: ma fonctionnalité"

git push origin feature/ma-fonctionnalite

Puis ouvrez une Pull Request sur GitHub.

---

📝 Messages de commit

Des messages de commit clairs sont recommandés.

Exemples :

Add: ajout de la recherche par référence
Fix: correction du lecteur audio
Improve: amélioration de l'affichage mobile
Docs: mise à jour du README
Refactor: simplification du système de recherche

---

🧪 Tests

Avant d'envoyer une Pull Request, vérifiez notamment :

- que l'application se charge correctement ;
- que les fonctionnalités existantes continuent de fonctionner ;
- que les fichiers JSON sont valides ;
- que les chemins vers les ressources sont corrects ;
- que l'application fonctionne correctement sur mobile ;
- qu'aucune donnée sensible n'a été ajoutée au dépôt.

---

📦 Dépendances et contenus externes

Avant d'ajouter une bibliothèque, une dépendance ou un contenu externe :

- vérifiez sa licence ;
- vérifiez ses conditions d'utilisation ;
- vérifiez qu'il peut être redistribué avec le projet ;
- documentez son utilisation lorsque nécessaire.

La licence MIT du code d'Aura · Deen ne s'applique pas automatiquement aux contenus tiers.

---

🔐 Sécurité

Ne publiez pas publiquement une vulnérabilité de sécurité sensible avant de l'avoir signalée aux responsables du projet.

Consultez "SECURITY.md" pour connaître la procédure de signalement.

---

🤝 Revue des contributions

Les Pull Requests peuvent être examinées avant leur intégration.

Une contribution peut être :

- acceptée ;
- modifiée ;
- mise en attente pour discussion ;
- refusée si elle ne correspond pas aux objectifs du projet ou aux règles du dépôt.

Les retours lors des revues doivent rester respectueux et constructifs.

---

🌍 Toute contribution compte

Vous n'avez pas besoin d'être un développeur expérimenté pour contribuer.

Vous pouvez aider en :

- signalant un bug ;
- proposant une idée ;
- améliorant la documentation ;
- corrigeant une faute ;
- améliorant l'interface ;
- vérifiant une référence ;
- partageant votre expérience utilisateur.

Chaque contribution peut aider à améliorer Aura · Deen.

---

📜 Licence

Les contributions au code d'Aura · Deen sont publiées conformément à la licence du projet.

Consultez le fichier "LICENSE" pour connaître les conditions applicables.

Les contenus provenant de sources externes peuvent être soumis à leurs propres licences et conditions.

---

❤️ Merci

Merci à toutes les personnes qui contribuent à améliorer Aura · Deen.

Aura · Deen est un projet communautaire : chaque contribution, petite ou grande, peut faire la différence.
